# agent-harnesses-exps

Лаборатория для экспериментов с mainstream-обвязками агентов (agent harnesses) на осень 2026 года. Цель — не сравнить бенчмарки, а построить **одних и тех же автономных агентов** в разных обвязках, прогнать их на **одних и тех же задачах** и записать, что в каждой обвязке пришлось делать словами, что стенами, а что она даёт из коробки.

Проект продолжает лонгрид «Обвязка агента: прошлое, настоящее и будущее» (polomodov.tech, 1 октября 2026) и доклад для Giga Conf 16 октября 2026: там — теория и срез рынка, здесь — руки.

## Метод в пяти строках

1. Один агент (`agents/`) — одна спецификация, независимая от обвязки: миссия, входы, выходы, границы, критерий остановки.
2. Одна задача (`tasks/`) — воспроизводимый эпизод: стартовое состояние, контракт результата, скрытая проверка.
3. Каждый прогон — запись по схеме `results/schema.json`: обвязка и её версия, модель, режим прав, песочница, ходы, стоимость, время, вердикт скрытой проверки. Число без обвязки — не число.
4. Где можно, одна модель во всех обвязках; где нельзя (родная модель обвязки), это записывается как отдельный факт.
5. Всё, что пришлось добавить в обвязку ради задачи, попадает в **реестр обвязки** (`docs/harness-ledger.md`): компонента → предположение о модели → доказательство → триггер перепроверки.

Полный протокол — в `docs/method.md`.

## Структура

```
AGENTS.md            карта репозитория для агентов (CLAUDE.md импортирует её)
docs/method.md       протокол эксперимента, классы доказательств, что записывать
docs/harnesses.md    матрица обвязок × семь частей, установка, статус
docs/harness-ledger.md  реестр обвязки (заполняется по ходу)
agents/              спецификации агентов, независимые от обвязки
tasks/               воспроизводимые эпизоды со скрытыми проверками
experiments/<h>/     всё, что специфично для обвязки: конфиг, хуки, запуск, заметки
results/schema.json  схема записи прогона
results/runs/        записи прогонов (одна папка на прогон)
scripts/             new-run, check
```

## Как сделать первый прогон

```bash
cp .env.example .env            # ключи провайдеров
npm run new-run -- --harness claude-code --agent a1-dossier --task T001
```

Команда создаст `results/runs/<дата>-claude-code-a1-dossier-T001/run.json` с пустыми полями. Дальше — по `experiments/claude-code/README.md`: запустить агента в этой обвязке на этой задаче, заполнить запись, прогнать скрытую проверку задачи и добавить строки в реестр.

Проверка всех записей и реестра:

```bash
npm run check
```

## Правила

- Ключи только в `.env` (в `.gitignore`). Агенты ключей не видят: их выдаёт обвязка.
- `tasks/*/check/` — скрытые проверки. Агент, решающий задачу, туда не смотрит; обвязка это должна запрещать, и это первая строка реестра для каждой обвязки.
- Каждый прогон — с полной записью. Прогон без записи не считается.
- Заявления вендора об их обвязке помечаются как заявления; своё измерение — как своё, с условиями.
