## Цель

Разобраться в сети, через которую GPU-узлы получают образы и веса моделей, и посчитать, сколько она стоит. На собеседовании по AI-инфраструктуре вопрос «почему счёт за NAT больше счёта за GPU» встречается чаще, чем вопросы про CUDA. Заодно получить VPC-модуль, который [ЛР47](LAB47-k8s-gpu-eks-autoscaling.md) возьмёт готовым.

## Проверяемая гипотеза

1. Загрузка 10 GB весов модели из S3 в приватную подсеть через NAT gateway стоит не меньше 0,40 USD за прогон только за обработку трафика NAT, а через gateway endpoint S3 эта статья равна нулю при той же или большей скорости.
2. Роль с доступом к одному префиксу S3 не позволяет прочитать соседний префикс и не позволяет записать в разрешённый: 0 из N попыток нарушения проходят.

Цена обработки трафика NAT в выбранном регионе (с датой и источником), объём весов и пороги фиксируются в протоколе до прогона. Цены — заявления AWS на дату доступа, не ваши измерения.

## Подготовка

## Порядок выполнения

1. **VPC.** Две зоны доступности, публичные и приватные подсети, один NAT gateway. Запишите план и время apply.
2. **Инстанс.** CPU-инстанс в приватной подсети с доступом через SSM Session Manager, без публичного IP и без SSH-ключа. У роли инстанса две отдельные политики: управляемая `AmazonSSMManagedInstanceCore`, без которой Session Manager не подключится, и собственная политика данных — только чтение префикса с весами. Проверки IAM в шаге 6 относятся к политике данных.
3. **Через NAT.** Без endpoint скачайте веса `aws s3 cp --recursive` в локальный диск. Запишите время, среднюю скорость и метрики NAT gateway в CloudWatch: `Sum(BytesOutToSource)` — скачанные байты, которые NAT отдал инстансу, и `Sum(BytesOutToDestination)` — запросы в сторону S3. Обработка NAT тарифицируется по трафику в обоих направлениях, поэтому в стоимость идёт сумма двух метрик.
4. **Через endpoint.** Добавьте gateway endpoint S3 к таблицам маршрутов приватных подсетей. Повторите загрузку, проверьте, что `BytesOutToSource` NAT почти не выросла.
5. **ECR.** Добавьте interface endpoints для ECR (api и dkr) и загрузите образ vLLM из своего ECR-репозитория. Сравните время `docker pull` с публичным реестром через NAT. Учтите почасовую стоимость interface endpoints.
6. **IAM.** Выполните N попыток нарушения: чтение соседнего префикса, запись, удаление, листинг другого бакета. Сохраните ответы `AccessDenied` и, если включён, вывод IAM Access Analyzer по политике.
7. **Teardown.** `terraform destroy`, затем `janitor.sh` из ЛР48. NAT gateway и Elastic IP — главные кандидаты на забытые ресурсы.
