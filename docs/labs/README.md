# Лабораторный практикум: модели, движки и агентные обвязки

Версия заданий: **07.10.2026**. Стенды для локального инференса — **Ryzen AI Max+ 395 / 128 GB / Linux** и **Apple M5 Max / 128 GB / macOS**. Практикум проверяет, как модель, GPU backend, inference engine и агентная обвязка влияют на решение одних и тех же задач. Его результат — ваши отчёты и воспроизводимые данные, а не заранее заданный победитель.

Это **35 лабораторных работ**: десять общих и локальных работ, девять отдельных работ по всем реализованным обвязкам, восемь работ о качестве, устойчивости и развитии системы и восемь работ Apple-ветки. В каждой есть цель, гипотеза, необходимые условия, пошаговые действия, пустые таблицы, комплект сдачи, критерии завершения и контрольные вопросы. Общий [протокол исследования](../method.md) сохраняет силу. [Каталог моделей](../local-model-candidates.md) и [матрица движков](../local-inference-engines.md) служат справочниками к заданиям.

## Учебный маршрут без API

[Учебный режим](practice.md) воспроизводит записанные синтетические события локально, не обращается к сети и не требует Docker или Ryzen:

```bash
npm run lab:practice -- --scenario retry-429 --session first-pass
```

Упражнение создаётся отдельно в `experiments/local-models/practice/`, не создаёт `run.json`, не оценивает модель и не заполняет выводы за учащегося. Другие сценарии — корректный tool round trip, оборванный поток и повтор действия после неоднозначного ответа. Для отчёта по разбору создайте отдельную сессию `lab:new` с `evidence_class=synthetic`; формат и перенос evidence описаны в инструкции режима.

## Как начать

Откройте корень этого репозитория. Команды Ryzen-ветки рассчитаны на Bash/Linux; ЛР28–34 — на native macOS, ЛР35 — на оба стенда с учётом их различий. ЛР01 и команды координатора переносимы. Пути относительны корня. Проверьте `node --version` (требуется ≥22), `git --version`, `bash --version`.

```bash
npm run labs
npm run lab:new -- --lab LAB01 --session first-pass
```

Вторая команда создаёт **новый пустой комплект отчёта**:

```text
experiments/local-models/measurements/LAB01-first-pass/
  report.md
  manifest.json
  measurements.tsv
  raw/
```

Затем откройте [ЛР01](LAB01-reproducibility.md) и выполняйте её шаги. Для другой работы замените `LAB01` на её ID. `--session` — ваш короткий английский идентификатор: например `baseline-01` или `rocm-02`; только строчные буквы, цифры и дефисы. Существующая папка не перезаписывается. Повтор опыта — новая сессия, а не новая запись поверх прежних результатов.

Для ЛР11–19 helper выбирает каталог соответствующей обвязки. Например:

```bash
npm run lab:new -- --lab LAB13 --session first-pass
```

создаёт `experiments/codex/measurements/LAB13-first-pass/` с теми же файлами. Старые пути ЛР01–10 остаются в `experiments/local-models/measurements/`; это сохраняет ссылки существующих отчётов, даже если ЛР09/10 выполняется с облачной моделью. Поле `harness_id` нового учебного manifest заполнено для отдельных harness-работ; для общих работ оно `null`.

Команда `lab:new` не устанавливает программы, не читает `.env`, не обращается к моделям и не создаёт `run.json`. Она не проверяет фактическое прохождение предыдущих работ: ссылки на их отчёты и выполнение условий указываете вы. `manifest.json` здесь — паспорт учебного отчёта, **не схема экспериментального run**. Общие ЛР20–27 используют тот же каталог `experiments/local-models/measurements/`, даже при облачном или учебном выполнении.

Каталоги сборок ЛР04, исходников SGLang ЛР06 и копий весов Ollama ЛР07 исключены из Git; исходные веса хранятся за пределами репозитория. Сохраняйте raw evidence в архиве отчёта: общий `.gitignore` исключает `*.log`, поэтому обычный Git commit сам по себе не переносит весь комплект доказательств.

## Общие правила выполнения

1. **Перед измерениями** заполнить гипотезу, изменяемый фактор, константы, порядок, число повторов и критерий остановки. Изменённый после начала опыт имеет новую конфигурацию; объяснение сохраните.
2. Выполнить сначала минимальный вариант своей работы. Полная матрица и большие модели — расширенное задание после успешного малого контроля. Часы в паспортах — ориентиры работы оператора, не гарантии скорости или срока.
3. Резервировать память под ОС и runtime; GPU и CPU делят физическую RAM. Самостоятельно не считать 128 GB весами, не складывать RAM с GPU heap. Vulkan и HIP/ROCm равноправны, фактический backend подтверждать логом.
4. Сохранять команды, effective config и raw output. Число без единиц, контекста, точности и условий не использовать в сравнении. `null`/пусто — неизвестное с причиной; `0` — только измеренный ноль. Примерные таблицы заданий остаются пустыми до выполнения.
5. Не выполнять произвольные tools из smoke-ответа модели. Для ЛР05–07 есть [открытые fixtures](fixtures/README.md) с единственной разрешённой функцией. В ЛР09–19 агентные инструменты работают в отдельной изолированной среде.
6. Не читать скрытые `tasks/*/check/` во время решения и разработки адаптеров; не менять `tasks/*/task.md`. Оценщик применяет проверки вне agent container. API credentials поступают из `.env` через harness; ключи не включаются в отчёт или исходные логи.
7. Не выдавать инфраструктурный smoke, учебный отчёт или exit 0 за успех задачи. Для автономной попытки обязателен отдельный `results/runs/<run-id>/run.json` и независимый verdict.
8. При невозможности продолжать сохранить наблюдения и точный blocker. Статус отчёта `blocked` или `in-progress` не считается выполненным минимальным заданием. Опровергнутая гипотеза или неудача модели может быть полноценным результатом, если метод и комплект сдачи выполнены.

## Как вести отчёт

[Общий шаблон](templates/report.md) копируется автоматически. В `report.md` вставьте специальные таблицы из задания, заполните ход работы и ответы на вопросы. В `manifest.json` укажите статус (`not-started`, `in-progress`, `completed`, `blocked`), исполнителя, ссылки на паспорта/артефакты, evidence и run IDs. Ссылки должны указывать на сохранённые материалы; поля, не применимые к работе, оставьте `null` с пояснением в `unavailable`.

Новые отчёты используют manifest v2: класс доказательств `evidence_class`, сохранённый предварительный протокол и полный реестр `planned_attempts`. [Инструкция проверки отчёта](report-validation.md) описывает пути, статусы попыток и переход со старой версии. Проверяйте черновик и затем комплект для сдачи:

```bash
npm run lab:check -- --report experiments/local-models/measurements/LAB01-first-pass
npm run lab:check -- --report experiments/local-models/measurements/LAB01-first-pass --mode submission
```

Второй вызов возвращает ошибку, пока не заполнены обязательные данные и не объяснены пропуски. Он проверяет ссылки, реестр попыток, метрики и реальные run records; содержательный зачёт остаётся за оценщиком.

В `measurements.tsv` одна строка — одно численное наблюдение. Заголовки:

| Поле | Значение |
| --- | --- |
| observation_id / configuration_id | Уникальная строка и конфигурация, связывающая её с manifest/report |
| model_id / engine / backend / context_tokens / repeat | Условия наблюдения; неприменимое оставьте пустым |
| metric / value / unit | Определённая метрика, измеренное значение, единица |
| status | `measured`, `failed`, `not-run` или `unavailable` |
| evidence_path / unavailable_reason | Путь к сырому свидетельству / причина отсутствия значения |

Среднее, median/min/max и сравнения выводятся в отчёте поверх исходных строк. Если численных измерений не было (например, только проектирование ЛР08), файл может содержать один заголовок; объясните это. TSV не является импортом для `compare`; CLI сравнивает только настоящие run records.

## Критерии приёмки практикума

У каждой работы свой checklist. При проверке комплекта дополнительно убедиться:

- В отчёте можно восстановить фактическую конфигурацию и порядок опыта.
- Есть все запланированные повторы, включая ошибки, либо объяснённые `not-run`.
- Гипотеза сопоставлена с данными, ограничения выводов перечислены.
- Приложены raw evidence, специальные таблицы и ответы на вопросы.
- Агентные verdict принадлежат оценщику, а не автоматически учебному шаблону.
- `npm run check` проходит; он проверяет структуру заданий, наличие отдельной работы для каждого harness profile, каталоги и run records, **не выставляет зачёт за отчёт**.

Маршрут по всем обвязкам завершён после критериев ЛР01, всех девяти ЛР11–19, облачной ЛР09 и ЛР10. Локальный маршрут завершён после критериев ЛР01–10 в его условиях. Базовый практикум объединяет эти 19 работ; полный практикум добавляет ЛР20–27 и Apple-ветку ЛР28–35. Общие завершённые работы не дублируются, но дополнительные маршруты и конфигурации получают собственные сессии и новые попытки. Расширенные серии внутри отдельной работы не являются её обязательным минимумом. Неизмеренные показатели и неподключённые движки остаются явно обозначенными; заранее заполненных результатов нет.
