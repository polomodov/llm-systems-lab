## Обезличенная история

При подготовке 2026-11-06 история веток переписана: личные адреса в Git
заменены на GitHub noreply, имя автора — на `polomodov`. Домашние каталоги,
имя машины, подтверждённые адреса LAN в access logs и ссылки на личные
Claude Code sessions заменены нейтральными значениями. Публичные имена
проектов и авторов, loopback, сетевые allowlists и тестовые адреса сохранены.

Затронутые архивы измерений и записи прогонов — производные копии.
`privacy-redaction.json` рядом с ними содержит исходные и опубликованные
SHA-256 изменённых файлов. В LAB-архивах ограничение также описано в
`PUBLICATION-REDACTION.md`, а в записях прогонов — в `notes`.
Служебные печати входов, артефактов и оценивания пересчитаны для новых
байтов; отпечатки локальных deployment изменились вместе с путями.
Проверки целостности не отключены.

Прогоны и оценивание повторно не выполнялись. Вердикты, токены, стоимость,
длительность и прочие численные результаты сохранены. Измеренные суммы
внешних моделей и бинарников, времена запуска и исходные ревизии описывают
исходный эксперимент. Они не являются доказательством нового запуска
или суммами обезличенных логов. Не включённые в Git рабочие каталоги
не восстанавливались. Исходная история хранится отдельно в закрытом
резервном архиве и не входит в публикуемые ветки.

## Работа после переписывания

SHA коммитов изменились. Для продолжения работы предпочтителен новый клон.
Не сливайте старые ветки в новую историю и не отправляйте их через force-push:
это вернёт исходные метаданные. Нужные незакоммиченные изменения переносите
проверенным patch, без старой истории. Для новых коммитов используйте
публичную Git-идентичность:

```bash
git config --local user.name polomodov
git config --local user.email 6575406+polomodov@users.noreply.github.com
mise trust
mise install
mise run verify
```

`mise.local.toml` и `.mise.local.toml` игнорируются Git. Секреты остаются
в `.env`; mise не загружает его. Версии инструментов и команды проверок
описаны в [README](../README.md#требования-и-образы).

## Граница очистки на GitHub

Переписывание веток не удаляет старые клоны, форки, кешированные SHA
и управляемые GitHub ссылки `refs/pull/*`. Описания затронутых PR очищаются
от прямых ссылок на личные сессии, но это не переписывает сохранённые GitHub
коммиты PR. Поэтому очистка не означает, что исходные метаданные невозможно
восстановить из старых ссылок. [GitHub описывает эти ограничения и порядок
обращения в Support](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).
Support не обещает удалять несекретные данные.

Подготовка файлов и истории сама по себе не меняет видимость репозитория.
