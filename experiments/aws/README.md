# AWS и Terraform: облачная часть AI-инфраструктуры

Каталог ветки [ЛР48–52](../../docs/labs/README.md#маршрут-aws-и-terraform). Здесь учебный AWS-аккаунт приводится в управляемое кодом состояние, строятся сеть и IAM под GPU-платформу, инфраструктурный код получает тесты и CI, а на кластере из [ЛР47](../../docs/labs/LAB47-k8s-gpu-eks-autoscaling.md) измеряются холодный старт и надёжность GPU-сервинга. Это не обвязка: `harness.json` в каталоге нет и быть не должно.

Статус: **методички готовы, измерений нет**.

## Стенд

| Стенд | Что это | Работы |
| --- | --- | --- |
| AWS, сессии `aws-NN` | Личный учебный аккаунт; управляющая машина — HONOR или Ryzen | ЛР48–50 без GPU; ЛР51–52 на кластере ЛР47 с одним-двумя небольшими GPU-инстансами |

## Что лежит здесь

| Путь | Содержимое | Появляется в |
| --- | --- | --- |
| `measurements/LABxx-session/` | Отчёты; создаются `npm run lab:new -- --lab LAB48 --session aws-01` | ЛР48–52 |
| `terraform/LAB48/`, `terraform/LAB49/`, `terraform/LAB50/` | Bootstrap state, бюджет и роль; VPC и IAM; конфигурация CI | ЛР48–50 |
| `terraform/modules/` | Модули VPC и GPU-пула, которые подключает ЛР47 | ЛР49, 50 |
| `janitor.sh` | Проверка остатков по тегам и типам ресурсов | ЛР48, далее в каждой AWS-сессии |

Изменения кластера в ЛР51–52 делаются поверх кода ЛР47 в [`experiments/k8s-gpu/terraform/`](../k8s-gpu/README.md). Подкаталоги создаются той работой, которой они нужны.

## Правила

- Учётные данные AWS, `terraform.tfstate`, `*.tfvars` с идентификаторами, kubeconfig и account ID не попадают в отчёты, raw и коммиты. Root-ключи не создаются.
- Перед любыми платными ресурсами включены бюджет и лимиты; ожидаемая стоимость сессии записана в протокол.
- Ресурсы живут только во время сессии: в конце `terraform destroy` и `janitor.sh` с пустым результатом.
- Цены AWS — заявления вендора с датой доступа; фактические расходы берутся из Billing; собственные измерения указываются с сессией.
