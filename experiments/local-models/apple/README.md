Without `--hardware`, both commands retain Ryzen/Linux regardless of the host OS. `--engine all` applies only to the selected machine. Unknown hardware/engine values cause an error. These commands do not install engines or run models.

Apple has `gpu_budget_gib=null`: `hardware-memory-required` means the final budget and headroom are unknown. Planned weight/runtime/KV sizes remain visible. After LAB28 and smoke checks, pass measured values through `--memory-gib` and `--gpu-budget-gib`; these neither update the profile nor change the OS. Even a numeric estimate retains `fit_verified=false`.

Status precedence: MLX requires its own artifact (`artifact-required`); a GGUF wrapper without runtime calibration gives `engine-memory-required`; known GGUF/runtime with unknown GPU memory gives `hardware-memory-required`; only then are `candidate`, `conditional`, or `over-budget` calculated. Without `--engine`, the earlier rough GGUF reserve model is used, not a universal engine estimate.

All five profiles have `hardware_support=conditional`: general Apple Silicon support does not verify the M5 Max/macOS/model/pinned-runtime combination. The Ollama profile applies to GGUF/Metal; another internal runner or format requires a separate condition. MLX does not inherit GGUF hashes, quantization, or sizes.

## Shared protocol for Apple labs

Track: LAB01 → [LAB28](../../../docs/labs/LAB28-apple-hardware.md) → LAB29 → LAB30/LAB31 → LAB32 → LAB33/LAB34 → LAB35. Requires Node.js ≥22, Python 3, and Git; builds require CMake and Xcode Command Line Tools, and MLX requires compatible native arm64 Python. The operator installs dependencies separately and records versions. Rosetta and containerized GPU inference are not conditions of this track.

Create each session through `lab:new`, without overwriting earlier sessions. Before execution, fill in `raw/protocol.md`, `protocol_recorded_at`, `conditions`, and `planned_attempts` in manifest v2 following the [report format](../../../docs/labs/report-validation.md). Measurements use `kind=measurement`, `run_id=null`; a launched model requires `evidence_class=experimental`. Agent attempts require actual `run.json` records. Preserve started failures and unexecuted conditions with reasons. Leave unknown TSV values empty with `unavailable_reason`; use `null` in JSON.

For each configuration: separate warmup and three measured repeats, identical inputs/output cap, sampling/reasoning, template, KV/state, slots, and cache policy. Record cold starts separately. Do not combine new CLI processes and a warmed HTTP server into one metric. Before LAB34: one model server and concurrency 1. Increase context/load only after reviewing the previous result, without automatic restart or cloud fallback.

Before a series, record acceptable latency/errors, memory reserve, and swap policy. The default OS reserve is 16 GiB; stop on critical memory pressure, sustained swap growth, OOM, lost readiness, or unverified GPU execution. Do not lower macOS safeguards or change power mode within a comparison. `recommendedMaxWorkingSetSize` is a recommendation, not a free heap; `vm_stat` free pages do not equal all available RAM. RSS and Metal/MLX allocations may describe overlapping pages.

Collect a time series in a second terminal (same `LAB_DIR`; start before the experiment and stop with Ctrl-C afterward):

```sh
while true; do
  date -u '+%Y-%m-%dT%H:%M:%SZ'
  vm_stat
  sysctl vm.swapusage
  memory_pressure -Q
  sleep 5
done > "$LAB_DIR/raw/macos-memory-series.txt" 2>&1
```

This observes pressure; it does not generate it: do not use artificial-load modes of `memory_pressure`. Periodic collection may miss the peak; also retain runtime peak memory and `/usr/bin/time -l`. macOS time reports maximum resident set size in bytes. Mark unavailable temperature/energy as unknown: slower execution alone does not prove throttling. `pmset -g custom` describes settings, not measured power.

Store logs as `.txt`: `.log` files are ignored by the repository. Keep large weights, engine sources, builds, and venvs outside evidence; do not commit them. Archive their versions, commands, and hashes. `raw/` and manifests contain only necessary evidence, without secrets or device serial numbers.
