# LAB34: протокол второго продолжения от 09.10.2026

## История и гипотеза

Первое продолжение `LAB34-apple-load-resume-20261009` остановлено в 08:27 UTC по переходу AC→Battery: прогрев 2/2, r2-c4 retry 11/12, один timeout. Собственный сервер получил один SIGINT и завершился с кодом 0. Отчёт остаётся blocked. Перед новым стартом требуется отдельная двухминутная серия admission samples с AC/mode 0 и прежними memory boundaries. Это новая зарегистрированная сессия, а не рестарт прерванного блока. Неудачный retry не переносится в успешную матрицу; его 14 запросов/1 ошибка включаются в историю наряду с 62/2 предыдущей кампании. Скопированные четыре блока 08.10 не считаются повторно. Для матрицы используются данные 08.10 и новой сессии 09.10; вся история охватывает три процесса/старта.

Предыдущая сессия `LAB34-apple-load-complete-20261008` остаётся `blocked`: во втором повторе c4 прошли 10 из 12 запросов, два завершились ошибками соединения. Native process получил SIGKILL; источник сигнала неизвестен, memory guard не сработал. Эти попытки сохраняются отдельно и входят в число всех начатых запросов.

Гипотеза: новый resident deployment завершит оставшиеся короткие серии и непрерывную нагрузку не менее 1800 секунд в прежних границах. Успешное продолжение не отменяет отказ предыдущей сессии.

Успешные блоки `r1-c1`, `r1-c2`, `r1-c4`, `r2-c2` повторно не запускаются. Их первичные records, responses, configs и summaries скопированы в `prior-short`; SHA-256 и источник с датой/PID закреплены в `prior-short-reference.json`. Это исторические измерения, а не новые запуски. Их проверка `prior-evidence-audit` — offline exercise.

## Порядок и условия

Порядок: audit → свежий preflight/startup → прогрев из двух запросов → отдельный retry `r2-c4` → `r2-c1` → `r3-c4` → `r3-c1` → `r3-c2` → выбор concurrency → 1800 секунд sustained → shutdown. Короткая матрица охватывает две сессии, два дня и два холодных старта; она не является непрерывной кампанией одного resident process.

Неизменны GGUF Qwen3.5-9B Q6_K, revision `3885219b6810b007914f3a7950a8d1b469d598a5`, SHA-256 `91898433cf5ce0a8f45516a4cc3e9343b6e01d052d01f684309098c66a326c59`; patched llama.cpp b8407 / `312cf03328496df9c56fe843952cf02a8964c59a` с tile16, server SHA-256 `916660e9bfe7f4d2fda420136f6bd192688def8cbd6581f23d08b06ead2e571f`. Перед запуском хеши проверяются заново. Metal на M5 Max и offload 33/33 подтверждаются логом новой версии процесса.

Параметры: context 8192, один server slot, threads 8, batch 512, ubatch 256, flash attention on, KV f16/f16, Jinja, no-context-shift, reasoning auto, enable_thinking=true, cache prompt off; loopback 18080. Тело `load-request.json` неизменно: запрос примерно 300 слов, temperature 0, seed 1, top_p 1, max_tokens 2048, без streaming и tools. Concurrency 1/2/4 означает клиентскую очередь к одному GPU-слоту; одновременные 2/4 GPU-слота не проверяются. В каждом коротком блоке 12 запросов; перед ним очередь idle.

## Остановка и выбор длинной серии

HTTP deadline — 300 секунд, допустимый p95 успешных ответов — не более 240 секунд, ошибок в допущенном блоке — ноль. Любая новая ошибка останавливает оставшиеся попытки.

Memory guard каждые две секунды требует free+speculative ≥8 GiB, pressure level 1, pressure free ≥50%, swap=0, native RSS ≤24 GiB, AC power и power mode 0. Все команды коллектора должны завершиться с кодом 0. При Battery Power новые GPU-измерения не начинаются. Резерв ОС 16 GiB в каталоге не меняется; операционный порог free+speculative — отдельное условие остановки.

Перед стартом и примерно каждые 20 секунд проверяются чужие модели LM Studio/Ollama. При их загрузке останавливается только собственный сервер. Настройки питания, системные лимиты, cache и чужие приложения не меняются. Cleanup защищён lock и отправляет один SIGINT; после 30 секунд допускается SIGKILL с записью причины. Caffeinate -i действует только во время жизни controller.

Для выбора используются девять успешных клеток с явным источником: четыре исторические и пять новых. Правило — минимальная concurrency, чья median requests/s по трём успешным блокам достигает 95% максимальной median среди c1/c2/c4. Выбор записывается до длинной серии. Старый неудачный r2-c4 показывается отдельно; выбор по успешной матрице не означает ноль ошибок во всей истории deployment.

Все 1800 секунд выполняются целиком в новом resident process после прогрева и коротких проверок. Короткие интервалы разных сессий не складываются. Последний блок из 12 запросов может закончиться позже 1800 секунд; сохраняются actual wall time, паузы и ошибки. Throughput всего интервала — сумма completion tokens успешных ответов / wall time всего интервала.

## Доказательства и границы

Сохраняются все requests/responses, usage, finish reasons, индивидуальные latency, summaries, props/slots/runtime, native log и macOS timeline до, во время и после запуска. Energy, temperature, TTFT, decode-only и максимальный GPU budget неизвестны с причинами. Ответы, обрезанные по max_tokens, не доказывают качество выполнения запроса.

Новый статус completed означает выполнение этого протокола продолжения, а не успешный допуск старой кампании. Автономный агент не запускается: run_ids=[]; это аппаратный учебный отчёт.
