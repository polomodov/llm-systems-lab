# LAB30/31 — общие HTTP входы, разные deployments

Source, inputs, model и native pins регистрируются до GPU. Порядок GGUF → MLX, один сервер. shared-inputs.json задаёт одинаковые user messages и expected final; прогрев плюс три повтора на вход. Model selectors различаются по API, но sampling одинаков: temperature=0, seed=1, top_p=1, output cap=256, thinking=false, SSE/include_usage. Raw finals должны буквально равняться LAB_READY и 2304, без нормализации. Сохраняются primary usage, TTFT content, total. При отказе будущие попытки not-run.

GGUF Q6_K revision 3885219b6810b007914f3a7950a8d1b469d598a5, tensor tile16 llama.cpp commit 312cf03328496df9c56fe843952cf02a8964c59a, KV f16/f16, context 8192, один слот, все 23 engine pins (21 dylib path) до Popen. MLX affine 4-bit/group64 revision 938d8919941c6e7efd3c7150eff7fe9d12afa631, MLX-LM 0.32.0 / MLX 0.32.3; все 12 model files и native/source pins проверяются до Popen. Default full-precision KV, без prompt cache, prefill step 2048. Это разные quantization/templates/engines: разницу нельзя приписать одному backend. Равенство messages не означает равенство template token IDs. MLX hard cap=null; бюджет коротких входов 8192 не является KV reservation.

Cold readiness измеряется от Popen отдельно. Warm repeats не объединяются с cold start. GGUF actual props/template/context/device/offload/tensor logs и MLX default device/allocator/loaded images проверяются. Resource guard: samples 2 с, gap ≤15 с, free+spec ≥8 GiB, pressure level 1, free percentage ≥50, swap 0, AC/mode 0, owned RSS ≤24 GiB. Один собственный процесс, caffeinate process-bound, SIGINT максимум один, shutdown 30 с. Общий deadline 900 с на deployment, HTTP probe ≤120 с с own client termination. Чужая модель или занятый порт означают отказ. ОС, kernel, wired limits и чужие приложения не меняются.

Температура, энергия и максимальный GPU budget неизвестны. Три повтора не доказывают эквивалентность и не оценивают качество агента. Агентные episodes требуют run.json и independent judge.
