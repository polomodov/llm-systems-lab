# LAB31 — протокол до запуска

Гипотеза: локальный MLX/safetensors Qwen3.5-9B 4-bit @938d8919941c6e7efd3c7150eff7fe9d12afa631 поддержан native arm64 MLX-LM0.32.0/MLX0.32.3 на M5 Max/macOS26.5; текстовый инференс идёт через default GPU без замены weights или CPU fallback. Это не проверка vision и не утверждение о качестве/скорости до замера.

Pins выбраны до установки по PyPI metadata и tagv0.32.0: Python3.12.14 arm64, mlx0.32.3, mlx-metal0.32.3, mlx-lm0.32.0. Модель ранее сконвертирована mlx-vlm; pinned qwen3_5.sanitize умеет исключать vision tower и сопоставлять language_model keys. Точные dependency versions и wheels фиксируются install-report/lock. Полные weights не скачиваются: проверить SHA всех12 MLX files из LAB29 перед загрузкой. Inference environment HF_HUB_OFFLINE=1, TRANSFORMERS_OFFLINE=1; trust_remote_code не включать.

Публичный prompt: «Объясни три причины проверять SHA-256 модельных весов. Ответь по-русски тремя короткими пунктами.» Сохранить prompt/template/tokenizer и rendered input hashes. enable_thinking=false, temperature0, seed1, output cap128. Один smoke/warmup и три последовательных CLI повтора в отдельных процессах; внутренний generation не объявлять прогретым HTTP server. Не подменять cap фактическим output. Runtime PP/TG, peak memory и /usr/bin/time -l RSS/wall сохранять с единицами/точностью. Нет speed acceptance threshold; успех — exit0, ненулевой текст, фактические tokens/metrics при доступности, GPU device/allocations, no swap growth.

Admission/stop: актуальная arm64/macOS/RAM и AC/powermode0; free pages>=16GiB, reserveOS16GiB, runtime/process peak<=24GiB, timeout600s. Telemetry2s: vm_stat, memory_pressure -Q, swap, pmset. Остановить при ошибке, swap growth, free-page floor, потере power condition, неподтверждённом GPU или неожиданной модели. Не менять системные лимиты и power mode. В выбранном MLX-LM штатный generate.wired_limit вызывает mx.set_wired_limit(device recommendation) и восстанавливает прежнее значение после генерации; это default process-local поведение runtime, не ручное tuning. Его фиксируем как отличие от методички «без wired-limit tuning»; новых значений оператор не задаёт, sysctl/wired tuning ОС не выполняется. При 24GiB ceiling это не исследование максимального device budget.

После CLI: один native server с тем же local path и venv на127.0.0.1:8081, concurrency1, фиксированный default model и offline environment. Проверить отсутствие чужого listener до запуска; HTTP readiness через /v1/models с deadline120s, сохранить status/body, advertised id и command. Дополнительный короткий text chat (max_tokens64, temperature0, enable_thinking=false) — только functional smoke; streaming/tools/long context LAB32. Остановить только свой child server после проверки, не оставлять background model.

Никаких агентных задач: run_ids пусты, evidence_class=experimental. Сравнение с LAB30 — таблица различий: MLX affine4-bit/group64 и GGUFQ6_K, templates/EOS/inputs/benchmarks разные; никакого чистого engine speed ratio. Повторные failures и not-run сохранять. Сдача: report/TSV/manifest/runtime locks/raw outputs, lab:check submission и npm run check. Исходные LAB28–30 не менять.
