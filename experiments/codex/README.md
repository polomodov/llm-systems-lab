# OpenAI Codex CLI

Пошаговое задание по `exec`, внешней изоляции, реальному T002 и разбору JSONL: [ЛР13 — Codex CLI](../../docs/labs/LAB13-codex.md).

Реализован адаптер `codex exec --json`. Версия **0.155.1** собрана и проверена 20.09.2026 на Linux/arm64 без credentials и доступной сети. Реальное выполнение эпизодов с провайдером остаётся **unverified**. [Исходные проверки](smoke/2026-09-20.json) не являются прогонами агента.

```bash
docker build --build-arg HARNESS_VERSION=0.155.1 \
  -t harness-lab/codex:0.155.1 experiments/codex
```

В `.env` нужен `CODEX_API_KEY`; координатор передаёт только выбранный ключ. Пользовательский `auth.json`, настройки и сессии с хоста не подключаются. Для подготовки выберите `--harness codex`, провайдер — `openai`; в запуске укажите точный доступный ID модели, образ и `--budget-mode observed`. Общие команды находятся в [корневой инструкции](../../README.md).

Адаптер явно задаёт модель, `approval_policy=never`, отключает встроенный web search и подагентов, а также загрузку пользовательских config/rules. Внутренний sandbox выключен через документированный `danger-full-access`; границы файлов, процессов и сети обеспечивает внешний контейнер лаборатории.

CLI не предоставляет проверенных флагов ограничения внутренних ходов и USD. Адаптер отклоняет такие обязательные лимиты. Исследовательский режим сохраняет отсутствие этих ограничений в записи; внешний timeout остаётся жёстким.

Парсер читает только корректный завершённый поток. `turn.completed.usage.input_tokens` уже содержит cache; второй раз `cached_input_tokens` не добавляется. USD и внутренние модельные ходы остаются неизвестными. `thread.started` даёт ID сессии, но JSONL не подтверждает ID модели в ответе провайдера: `observed_id=null`. Ошибка или обрыв не превращается в успешное завершение.

Первичные источники: [OpenAI Docs — non-interactive mode](https://developers.openai.com/codex/noninteractive), [config reference](https://developers.openai.com/codex/config-reference). Установочный пакет — `@openai/codex@0.155.1`. Конкретные флаги дополнительно сверены с `codex exec --help` внутри образа. При обновлении повторите smoke и тесты парсера, затем проведите записанный эпизод; строка компонента — **L009**.
